# Velocity Architecture for Temlis Figma-to-Website Pipeline

This is the canonical architecture rule for the Temlis pipeline on top of the Velocity Astro starter. Claude and Codex rules must stay synchronized with this file.

## Project Model

Velocity is an Astro 6 and Tailwind v4 starter. Tailwind utilities are generated from CSS custom properties declared in `@theme` inside `src/styles/global.css`. Figma-to-code work must adapt the existing token system instead of replacing it with a separate scaling model.

## Token Files

Editable token values:

- `src/styles/tokens/primitives.css`: OKLCH primitive color scales, including `--brand-*`, neutral scales, and project accents.
- `src/styles/tokens/typography.css`: `--text-*` clamp values, `--leading-*`, `--tracking-*`, and font weight tokens.
- `src/styles/tokens/spacing.css`: semantic spacing tokens such as `--space-section-*`, `--space-content-*`, `--space-container-*`, and `--space-heading-gap`.
- `src/styles/tokens/borders.css`: semantic border width and border color tokens.
- `src/styles/themes/default.css`: semantic colors, font stacks, shadows, radii, heading weight/tracking, and body leading.
- `src/styles/global.css`: Tailwind `@theme` bridge, font imports, container max width, and project-level utilities.

Stable structure:

- Keep token names stable unless a repeated Figma pattern requires a new semantic token.
- Keep the import cascade: Tailwind, color tokens, typography, spacing, borders, fonts.
- Keep the base spacing scale `--space-0` through `--space-96` aligned with Tailwind's 4px grid.
- Keep Tailwind v4 `@theme` as the bridge from CSS variables to utility classes.

## Tailwind Theme Bridge

Agents must use utility classes generated by `@theme`, not raw component CSS. Examples:

- `--background` becomes `bg-background`.
- `--brand-500` becomes `text-brand-500`, `bg-brand-500`, or `border-brand-500`.
- `--space-section-lg` becomes `py-space-section-lg`.
- `--space-container-xl` becomes `px-space-container-xl`.
- `--semantic-border-width-heavy` becomes `border-heavy`.
- `--border-color-strong` becomes `border-border-strong`.

If a semantic token exists but a class is missing, add or correct the `@theme` bridge or a small `@utility`. Do not fall back to repeated arbitrary values.

## Core Rules

1. Use Tailwind utility classes from Velocity tokens.
2. Do not use the old em-based pipeline (`--size-container-ideal`, `--size-font`, `--container-padding`, or component-level em conversion).
3. Do not write raw CSS values in components when a Tailwind utility, token, or semantic class can represent the value.
4. Use semantic spacing for layout rhythm: `py-space-section-*`, `px-space-container-*`, `gap-space-content-*`, `gap-space-section-*`, `gap-space-heading`.
5. Use scale utilities for local component spacing: `p-4`, `gap-6`, `mt-8`, `text-base`, `text-3xl`.
6. Use semantic border classes: `border-default border-border-default`, `border-heavy border-border-strong`, `divide-border-muted`.
7. Use OKLCH for primitive colors in token files.
8. Use unitless line-height tokens and exact Figma letter-spacing values when needed.
9. Install fonts with `@fontsource-variable/*` and map them through `--theme-font-*`.

## Figma px Mapping

Use Tailwind scale classes when values fit:

| Figma value | Preferred utility |
| --- | --- |
| 4px spacing | `p-1`, `gap-1`, `m-1` |
| 8px spacing | `p-2`, `gap-2`, `m-2` |
| 12px spacing | `p-3`, `gap-3`, `m-3` |
| 16px spacing/font | `p-4`, `gap-4`, `text-base` |
| 20px spacing/font | `p-5`, `gap-5`, `text-xl` |
| 24px spacing/font | `p-6`, `gap-6`, `text-2xl` |
| 32px spacing | `p-8`, `gap-8` |
| 48px spacing/font | `p-12`, `gap-12`, `text-5xl` |
| 64px spacing | `p-16`, `gap-16` |

For values that do not fit:

1. Check for an existing semantic token.
2. If the pattern repeats, add a semantic token and `@theme` bridge.
3. Use an arbitrary value only for a one-off Figma fidelity exception and document it near the component or in `QA_REPORT.md`.

## Layout Pattern

Every section uses a full-width section and a centered Velocity container:

```astro
<section class="w-full py-space-section-lg bg-background">
  <div class="container">
    <div class="grid gap-space-content-lg">
      ...
    </div>
  </div>
</section>
```

The `.container` utility owns max width and semantic inline padding. Do not add `px-*` to every container unless the Figma section is a documented exception.

Use mobile-first responsive classes:

```astro
<section class="w-full py-space-section-sm md:py-space-section-md lg:py-space-section-lg">
  <div class="container">
    <div class="grid grid-cols-1 gap-space-content-md md:grid-cols-2 lg:grid-cols-3 lg:gap-space-content-lg">
      ...
    </div>
  </div>
</section>
```

Use `max-[991px]:` only for navigation collapse or a Figma-specific breakpoint that cannot be represented by the standard Tailwind breakpoints.

## Component Reuse and Extraction

Check existing Velocity UI components before building new ones:

- Buttons: `src/components/ui/form/Button/`
- Cards: `src/components/ui/data-display/Card/`
- Badges: `src/components/ui/data-display/Badge/`
- Avatars: `src/components/ui/data-display/Avatar/`
- Inputs: `src/components/ui/form/Input/`
- Accordion: `src/components/ui/overlay/Accordion/`
- Tabs: `src/components/ui/overlay/Tabs/`
- Dialog: `src/components/ui/overlay/Dialog/`

Destination rules:

- `src/components/ui/...`: generic reusable primitives with no domain content.
- `src/components/blocks/...`: reusable marketing/content blocks.
- `src/components/sections/...`: complete page sections composed from UI and blocks.

If a Figma pattern appears in two or more places, extract it before composing sections. Do not duplicate cards, buttons, badges, stat items, testimonial items, logo items, pricing cards, or nav items inline across sections.

New reusable components should use CVA for variants, `cn()` from `src/lib/cn.ts` for class merging, Astro as the default static export, and React only when interactivity or an existing dual-export pattern requires it.

## Figma MCP First

Do not hardcode MCP server names in reusable docs. At runtime, detect available Figma tools first. The required conceptual workflow is:

1. Read metadata for the Figma URL.
2. Call design-context tooling for the page or section.
3. Call screenshot tooling for visual reference.
4. Build from live Figma context and screenshot, not from summaries.

If no Figma MCP/tool is available, stop with a clear message instead of pretending to have inspected the design.

## Raw Value Exception Policy

Allowed raw values:

- Token definitions.
- 1px-like primitives wrapped in semantic border tokens.
- One-off Figma fidelity exceptions that do not repeat and are documented.
- Intrinsic asset dimensions and aspect ratios.
- Letter-spacing values from Figma when token mapping would be less accurate.

Disallowed in components:

- Repeated `p-[37px]`, `gap-[22px]`, `border-[1px]`, or raw `var(...)` arbitrary classes when a token/class can exist.
- Raw hex colors instead of semantic color tokens.
- Inline `style=""` for values expressible with Tailwind or tokens.

## Required Artifacts

Phase outputs must use these contracts:

- `PROJECT_BRIEF.md`: Figma source, fileKey, analyzed frame/page, color/font/type/spacing/border/radius/shadow mappings, font imports, token decisions, and fidelity exceptions.
- `SITE_MAP.md`: Figma source, routes, sections, node IDs, screenshot references, local assets, component inventory, and layout dependencies.
- `IMAGE_MANIFEST.md`: Figma source layer/node, export URL or export method, local asset path, detected file type, file size, validation status, and placeholder notes.
- `QA_REPORT.md`: sections checked, fidelity differences, raw value exceptions accepted/rejected, component extraction issues, responsive issues, fix status, and remaining risks.
